# Architecture Decision Records (ADRs)

**Purpose:** One file per significant, deliberate engineering decision —
what was chosen, what alternatives were considered, and why. This is
where trade-off reasoning lives in detail, rather than being folded into
the specification documents themselves.

**Expected files:** Numbered, dated ADR files (e.g.
`0001-modular-monolith.md`, `0002-self-built-authentication.md`), seeded
initially from the Technical Design Document's Architecture Decision
Summary. None yet added.

**Relationship to other documentation:** A supporting, cross-cutting
record that explains the *why* behind decisions already embedded in
`docs/product/`, `docs/ux/`, `docs/architecture/`, `docs/database/`, and
`docs/api/`. ADRs do not introduce new decisions of their own — they
document ones already reflected elsewhere.
